幾個值得注意的細節：

- **繁體版比簡體版來得早。** 《少，但是更好》比簡體版早了一年半；《努力，但不費力》與 Effortless 英文版只隔八個月，比簡體版也早了兩三個月。
- **臺版兩本書同日出新版。** 天下文化在 2021-12-29 同時推出了《少，但是更好（新編增訂版）》和《努力，但不費力》，顯然是當作一套書來經營的。2025 年，天下文化又把《少，但是更好》和一本《90天生活實踐》（周群英 譯）合成兩冊套書。
- **作者譯名不同。** 臺版作者名譯作「葛瑞格．麥基昂」，簡體版譯作"格雷戈·麥吉沃恩"。

天下文化的作者簡介寫道：作者在史丹佛大學與人合開「設計精簡生活」（Designing Life, Essentially）課程，曾獲世界經濟論壇任命為「青年全球領袖」，並主持 Podcast《What's Essential》。

## 二、兩岸譯本對照：同一套框架，兩種中文

把三個版本的目錄放在一起讀，最大的收穫不是資訊量，而是**譯名本身就是一種解讀**。

### 1. 書名：一個強調"主義"，一個強調"取捨"與"努力"

簡體版把兩本書譯成"××主義"，讀者一眼就知道它們是一個系列。臺版的書名走了另一條路：

- 《少，但是更好》直譯作者的口號 *Weniger aber besser*。
- 《努力，但不費力》把一對看似矛盾的詞放在一起。

我認為後者翻得更準。"輕鬆主義"四個字很容易被讀成"偷懶有理"，而「努力，但不費力」先承認了努力，再討論怎樣不白費力氣。這正是作者在訪談裡反覆澄清的那條線（見第四節）。

### 2. 《精要主義》的三步：精挑、簡化、準確執行

臺版把 Essentialism 譯作「專準主義」，並把三個部分壓縮成一個口訣：「精．簡．準」。時任臺大管理學院院長的郭瑞祥在推薦語裡寫道，這本書在教人成為「精．簡．準」（精挑、簡化、準確執行）的專業工作者」。

| 英文 | 簡體中文版 | 繁體中文版（臺灣） |
|---|---|---|
| Essence（核心思維） | 核心思維模式：選擇 / 甄別 / 取捨 | 追求本質：懂得選擇 / 懂得辨別 / 懂得取捨 |
| Explore | 探索：抽離 / 審視 / 遊戲 / 睡眠 / 精選 | 精挑：逃離 / 留意 / 玩樂 / 睡眠 / 嚴選 |
| Eliminate | 排除：澄清 / 勇氣 / 放棄 / 編輯 / 邊界 | 簡化：釐清 / 膽量 / 取消承諾 / 剪輯 / 界線 |
| Execute | 執行：緩衝 / 掃除 / 進步 / 心流 / 專注 | 準確執行：緩衝 / 減法 / 進展 / 心流 / 專注 |

幾處差異值得注意：

- **Eliminate**：簡體版譯作"排除"，臺版目錄的部名卻叫「簡化」，副標題是「如何排除瑣碎的多數？」。天下文化刊出的前言書摘裡，同一步又寫作「簡化、排除」。創業媒體 Innopreneur 的繁體文章則用「消除」。這樣一來，*Effortless* 第八章 Simplify 在簡體和繁體裡都叫"簡化"，但在臺版《少，但是更好》裡，「簡化」指的是刪專案。兩本書合讀時，一定要分清兩個"簡化"：前者刪的是要不要做的事，後者刪的是怎麼做裡的步驟。
- **Unschedule / Subtract**：簡體版的"放棄"、"掃除"，臺版分別作「取消承諾：停損贏更大」和「減法：移除障礙，事半功倍」。「減法」兩個字比"掃除"更貼近原意：不是加把勁，而是拿掉阻礙。
- **新編增訂版的改動**：臺版新編增訂版把二十章加附錄改排成〈二十一天專準主義挑戰〉的第一天到第二十一天，比如「剪輯：隱形的藝術」「界限：有界限，才有自由」。初版目錄裡的「界線」也改成了「界限」。

### 3. 《輕鬆主義》：臺版譯名更"動作化"

| 英文 | 簡體中文版 | 繁體中文版（臺灣） |
|---|---|---|
| Effortless State | 輕鬆狀態：倒置 / 享受 / 釋懷 / 休息 / 覺察 | 不費力的狀態：翻轉 / 享受 / 釋放 / 休息 / 察覺 |
| Effortless Action | 輕鬆行動：定義 / 開始 / 簡化 / 過程 / 節奏 | 不費力的行動：界定 / 起跑 / 簡化 / 推進 / 步調 |
| Effortless Results | 輕鬆成果：學習 / 提升 / 自動 / 信任 / 預防 | 不費力的成果：學習 / 提升 / 自動化 / 信任 / 預防 |

臺版的章名副標題也很好用，幾乎可以直接當成工程團隊的口號：

- 「界定：『完成』是什麼樣子」
- 「起跑：顯而易見的第一步」
- 「推進：產出垃圾的勇氣」
- 「步調：慢即穩，穩即快」
- 「自動化：做一次就好」
- 「信任：發動高績效團隊的引擎」

## 三、兩本書各自講了什麼

### 《精要主義》：做"對的事"

出版社的定位一句話說清了這本書："Essentialism isn't about getting more done in less time. It's about getting only the right things done."（精要主義不是在更少的時間裡做更多事，而是只做對的事。）

天下文化刊出的前言書摘裡，作者講了一段親身經歷：女兒剛出生幾個小時，同事寫信說那天下午的客戶會需要他出席，他去了。事後他承認那場會「毫無成果可言」，自己「在想讓每個人都開心的情況下，我犧牲了最要緊的事」。他從中得到的教訓是：

> 「如果你不替自己的生活排定優先次序，別人就會代勞。」（《少，但是更好》前言書摘，天下文化 Bookzone）

作者用"整理衣櫃"來比喻全書的三步：

1. 不問「我以後還有沒有機會穿這件衣服？」，而問「我喜歡這件衣服嗎？」；
2. 把不要的真正裝袋送走；
3. 建立一套定期清理的例行流程。

### 《輕鬆主義》：把對的事"做輕鬆"

官網和出版社的簡介點出了它要反駁的信念："That if we want to overachieve, we have to overexert, overthink, and overdo."（想要超常成就，就必須用力過猛、想得過多、做得過頭。）它的立場是："The effortless way isn't the lazy way. It's the smart way."（輕鬆之道不是偷懶之道，而是聰明之道。）

臺版的文案換了個說法講這件事：我們習慣把事情分成「困難而重要」和「簡單而瑣碎」兩類，「其實我們還有第三種選擇：把重要但困難的工作變得簡單。」（天下文化《努力，但不費力》書籍頁）

## 四、整合：一個講"做什麼"，一個講"怎麼做"

### 1. 證據：第一本書就預告了第二本

把兩本書看成"上下集"，並不只是我的讀法。天下文化刊出的《少，但是更好》前言書摘裡，作者在講第三步時寫道：

> 「一旦你釐清要保留的是哪些活動和努力⸺⸺使你能做出最高程度貢獻的那些⸺⸺你就需要一套能讓你盡可能輕鬆執行意圖的系統。在本書中，你將學習創造出一個使必要的事情盡可能輕鬆完成的過程。」

Innopreneur 的文章引用了原書中的英文："While Nonessentialists tend to force execution, Essentialists invest the time they have saved by eliminating the nonessentials into designing a system to make execution almost effortless."（非精要主義者傾向於硬推執行；精要主義者則把排除雜事省下的時間，投入到設計一套讓執行幾乎不費力的系統上。）這裡已經出現了 effortless 這個詞。

作者在 Jordan Harbinger 的訪談裡，也把《精要主義》的落點概括為"how to build systems to make execution of what is essential, as easy as possible"（建立系統，讓精要之事執行起來儘可能容易）。

《努力，但不費力》的臺版書摘則把接力棒說得更直接：

> 「當手上重要的事已經超出你所能負荷，你可以選擇割捨，或是找輕鬆的方法來做。《努力，但不費力》要談的則是，用對的方法來做對的事。」（〈別把「過勞倦怠」當成榮譽勳章！〉，天下文化 Bookzone，2021-12-22）

臺灣讀書部落格「超閱者」的一句話概括，正好是本文的標題：「如果說《少，但是更好》是教你如何做對的事情；這本書則是教你如何用對的方法來做對的事。」

### 2. 精要主義的陷阱：減法做完了，剩下的仍然在硬扛

精要主義最常見的失敗方式，並不是沒做減法，而是做完減法後，用加倍的意志力去對付剩下的每一件事。"既然這件事最重要，就該拼盡全力。"結果是：重要的事少了，人卻更累了。

臺版書摘開篇講了 Patrick McGinnis 的故事。他在 AIG 每週工作 80 小時，2008 年公司崩盤，他手上的股票跌了 97%。他事後的結論被譯成：

> 「我解決所有問題的方式，就是花更多時間、再努力一點。」但突然之間，他發現，「再努力一點的邊際報酬竟然是負的。」

作者由此得出的教訓是：「當你已經沒辦法再多努力一點，就是時候另覓出路了。」作者和天下文化編輯張彤華的導讀都借用了《動物農莊》裡的馬「拳擊手」：牠面對每一次挫折和每一個難題，回答總是「我會更努力的。」，最後積勞成疾，被送進老弱家畜屠宰場。

作者在 Next Big Idea Club 的長文裡，講的是女兒 Eve 重病的經歷。這件事絕對屬於精要，但這場仗要打多久沒人知道："If your job is to keep the fires burning for an indefinite period, you can't throw all the fuel on the flames at the beginning."（如果你的任務是讓火無限期地燃燒，就不能一開始把所有燃料都扔進去。）

所以兩本書合起來，構成一個完整的閉環：

```
          《精要主義》：做什麼                    《輕鬆主義》：怎麼做
  ┌──────────────────────────────┐    ┌──────────────────────────────────┐
  │ 核心思維：選擇 / 甄別 / 取捨    │──▶│ 輕鬆狀態：倒置 / 享受 / 釋懷 / 休息 / 覺察 │
  │ 探索（精挑）：抽離 審視 遊戲 睡眠 精選│ │  （先把"人"調到能清醒選擇的狀態）       │
  ├──────────────────────────────┤    ├──────────────────────────────────┤
  │ 排除（簡化）：澄清 勇氣 放棄 編輯 邊界│─▶│ 輕鬆行動：定義 / 開始 / 簡化 / 過程 / 節奏 │

  ├──────────────────────────────┤    ├──────────────────────────────────┤
  │ 附錄：精要領導者               │──▶│ 輕鬆成果：學習 / 提升 / 自動 / 信任 / 預防 │
  │                              │    │  （讓一次投入產生持續回報）               │
  └──────────────────────────────┘    └──────────────────────────────────┘
     問：這件事值得做嗎？（臺版：「現在所做的事情，是否值得投入？」）
```

再細一點，可以按章節對應：

| 問題 | 精要主義（簡 / 繁） | 輕鬆主義（簡 / 繁） | 關係 |

| 怎樣排障？ | 掃除 / 減法 | 預防、自動 / 自動化 | 前者治當下的瓶頸，後者防未來的重複 |
| 團隊層面 | 精要領導者 | 提升、信任 | 後者講槓桿和信任結構 |

### 3. 一個關鍵區分：輕鬆不等於偷懶

作者在訪談裡專門劃了這條線："Lazy is an unwillingness to work. Easy is just something doesn't require a lot of effort to get it done."（懶是不願工作；容易只是指一件事不需要大量努力就能完成。）他還說："Effort is a finite resource."（努力是有限的資源。）

臺版文案的說法幾乎一致：「問題在於動力和努力都是有限的資源，我們愈是消耗，就愈容易過勞」。這句話把兩本書統一成一個經濟學問題：精要主義管"把有限的努力投向哪裡"，輕鬆主義管"每單位努力能換來多少產出"。

### 4. 技術負責人身上的典型陷阱

我見過不少技術負責人，精要主義做得很好：季度目標只留三個，雜事推得乾乾淨淨。可那三件事，每一件都靠自己通宵頂上去：核心模組自己寫，關鍵評審自己看，線上事故自己衝在第一線。

短期看，這是"聚焦"；長期看，這就是拳擊手式的「我會更努力」。團隊的能力沒有長起來，負責人自己成了系統裡唯一的瓶頸，也就是《精要主義》裡的"最慢行進者"。

輕鬆主義給的出路不是"再砍一件"，而是換一個問題：怎樣讓這件事不依賴我的透支也能完成？答案往往落在三個地方：

- 把知識寫下來，讓別人能接手（學習、提升）；
- 把重複勞動交給指令碼（自動）；
- 把決策權交給可信的人（信任）。

## 五、放到工程師與技術負責人的日常

### Backlog 排序：先用精要主義砍，再用輕鬆主義拆

- **砍**：給每個需求問一句，它能不能進前 10%？豆瓣讀者摘錄的簡體中譯本裡有一句判斷規則："如果答案不是一個確定的yes，那麼就應該是一個肯定的no"。真實的 backlog 很難做到這麼絕對，但可以把"不確定"的需求統一放進"下季度再評估"，不讓它佔用本迭代的容量。
- **拆**：對留下的需求，依次問輕鬆主義的幾個問題：完成長什麼樣？哪些步驟可以刪掉？第一個顯而易見的動作是什麼？

### 說"不"：把拒絕做成機制，而不是每次靠勇氣

天下文化刊出的「界限」一章書摘，開頭引了 Anne Lamott 的一句話：「不，就是完整的句子。」這一章裡有兩個對工程團隊特別有用的做法。

**一是「社會契約」。** 作者和一位作風相反的同事搭檔，第一次開會就先講清各自的優先事項，以及自己願意或不願意承擔的額外工作。

**二是「別搶他人的問題」。** 原文是：「一旦我們替他們扛下問題，我們所做的一切不過是在奪走他們解決問題的能力而已。」

這兩點可以沉澱成輕鬆主義式的"一次性決定"。出版社簡介的說法是"Make one-time choices that eliminate many future decisions"。落到團隊裡：

- 公開 intake 規則和本季度目標，不在目標裡的需求，預設進入排隊；
- 設立值班"介面人"，其餘人預設不接插單；
- 專案啟動會先寫一份"社會契約"：本期目標、各自不接的事、升級路徑。

作者在同一章裡提醒：「如果你不設定界限，就不會有任何界限。」《遠見》雜誌 2014 年的報道引了另一句：「只要你無法對不必要的事情說不，就等於在消極被動情況下說好。」

### 定義"做完"：避免瓦薩號式的範圍蔓延

在訪談裡，作者和主持人談到了那艘瑞典戰艦（瓦薩號）。作者說它"not fit for purpose"（不適合它原本的用途），因為造船的人從來沒有定義清楚"完成"長什麼樣。主持人當場就把它類比成軟體專案裡的 feature creep（功能蔓延）。

工程上的對應物就是 Definition of Done：驗收標準、效能指標、回滾方案、文件，在開工前寫下來。作者給自己的書定過一個"完成"的樣子："I've given this to my editor and she has looked through all of the chapters and said, 'Every one of them is solid and great.'"（我交給編輯，她看完所有章節後說：每一章都紮實而出色。）這個標準是可觀察的，不是"我覺得寫好了"。

### 第一個顯而易見的動作 + 零稿

作者在訪談裡說，完美主義讓人遲遲不開始；他的辦法是寫一份"零稿"："You don't publish rubbish, but you got to be willing to stare at rubbish."（你不會發布垃圾，但必須願意直視垃圾。）臺版第九章的章名把這個意思譯得很傳神：「推進：產出垃圾的勇氣」。

落到工程上就是：

- 先開一個 Draft PR；
- 先寫一個能跑通主路徑的 spike；
- 設計文件先寫成提綱，第一天就請同事看。

第一個動作應該簡單到不需要任何心理建設，比如"新建分支，寫一個失敗的測試"。

### 節奏：給工作量設上下限，也給恢復留出時間

作者用阿蒙森與斯科特的南極競賽說明節奏的價值：阿蒙森堅持每天前進約 15 英里，"no more and no less"（不多也不少）。作者建議給工作量同時設下限和上限，例如寫書"never write less than 500 words a day, but never more than a thousand"（每天不少於 500 字，也不多於 1000 字）。

臺版「休息」一章的書摘給了一條更嚴格的規則：

> 「切勿在一天之內做超過隔天一早可以完全恢復的事情，切勿在一週之內做超過隔週一開始可以徹底恢復的事情。」

書摘還給了一個具體排法：「利用早上處理重要工作」，「分三個時段工作，每個時段不超過90分鐘」，中間休息 10 到 15 分鐘。

工程團隊的對應做法是：

- 設 WIP（在製品）上限；
- 每天至少合併一個小 PR，但不在一天裡堆十個；
- 上午留出兩到三個不開會的深度工作塊；
- 值班或救火之後，第二天主動降負荷。

《遠見》的報道還提到，LinkedIn 執行長 Jeff Weiner 每天會在行事曆裡預留兩個小時空檔。

### 自動化與預防：時間管理的"長尾"

作者舉過一個例子：有人被一隻卡住的抽屜煩了兩年，修好它只用了兩分鐘。他的總結是："it usually takes less time to manage a problem than to solve it."（應付一個問題，通常比解決它花的時間少。）這正是 SRE 說的 toil（重複性雜務）。目標是"find the most annoying thing that can be solved in the least amount of time"（找到最煩人、又能用最少時間解決的那件事）。

臺灣「閱讀前哨站」的書評補了一個有意思的視角。作者把"檢查清單"放進「自動化」一章，書評把它概括為「大腦決策的自動化」。書評裡還舉了一個例子：有人原本每到交週報那天都要忙到很晚，後來改成每天下班前用一到兩行話記下進度，到交週報時只要整理一下就行。

對工程團隊來說，可以這樣落地：

- 用指令碼替換手工釋出、手工對帳；
- 把釋出、回滾、事故處置寫成 checklist 和 Runbook，相當於"決策的自動化"；
- 每天在工單裡留一行進展，週報自動彙總；
- 在復盤裡追問"怎樣讓這類問題根本不會發生"，對應「預防：預見問題，防患未然」一章。

### 信任：低信任結構是自動出現的

豆瓣讀者摘錄的第 14 章簡體中譯本裡寫道：在低度信任結構中，"規則模稜兩可，沒人知道成功的標準是什麼"；而"低度信任結構通常是自動出現的，而不是有意為之"。

技術負責人要刻意搭建高信任結構：

- 寫清楚每個模組的 owner；
- 寫清楚介面契約和 SLO；
- 寫清楚什麼情況下可以自行決定。

信任一旦建立，Review 和審批就可以變輕。臺版把這一章叫做「信任：發動高績效團隊的引擎」。

## 六、我的思考：兩本書的不足

**第一，過度假設個人擁有選擇權。** 兩本書的讀者畫像，是能夠自主安排時間的知識工作者。一線工程師的 backlog 往往由產品、老闆和合規要求共同決定，"確定的 yes 或肯定的 no"在組織裡很難由個人說了算。

有意思的是，「界限」一章的書摘裡，作者自己也承認：「界限確實可能付出昂貴的代價。」我認為更現實的做法是把精要主義上移到團隊層面：由技術負責人和產品負責人一起做取捨，再由個人去執行輕鬆主義。

**第二，故事多、證據少，第二本更淺。** 兩本書都大量依靠故事：南極競賽、瓦薩號、抽屜、女兒的病、McGinnis 的 AIG 往事。故事好記，但因果關係往往被簡化了。以斯科特的失敗為例，常見的解釋遠不止"節奏"一項，還包括運輸方式和補給安排。

「閱讀前哨站」的評價很中肯：他對《少，但是更好》評價不錯，但《努力，但不費力》讓他覺得有點「搔不到癢處」，每個小節篇幅太短，讀起來「淺嚐即止」。如果你想「學習實踐步驟」，這本書「比較像是給予一些原則和基本指引」。這和豆瓣短評裡"主旨很好……但是內容稍顯囉嗦"的感受，算是兩岸讀者的共識。

**第三，"輕鬆"容易被濫用。** 作者再三強調"easy does not equal lazy"，但在團隊裡，"找更輕鬆的路"也可能被用來跳過測試、省略評審。臺版書名「努力，但不費力」在這點上是一個很好的提醒：努力本身沒有被取消。我的補丁是：可以簡化步驟，不能降低"完成"的標準。先定義完成，再談輕鬆。

**第四，重複和"雞湯感"。** 兩本書有大量重疊，比如休息與睡眠、邊界與節奏、小勝。如果只讀一本，我建議讀《精要主義》的框架，再把《輕鬆主義》當作"執行"部分的工具書來查。

**第五，宗教與個人信仰色彩。** 天下文化刊出的《少，但是更好》書摘（從內容看出自最後一章「存在」）從甘地寫到釋迦牟尼、摩西、穆罕默德和耶穌，稱「專準主義在許多靈性和宗教傳統中具有深厚的根基」。《努力，但不費力》的「釋放」一章則大量討論感恩。這些內容對部分讀者有幫助，但不是方法的必要組成部分，閱讀時可以剝離開。

## 七、可執行清單

1. **每季度做一次"前10%"篩選**：列出所有專案，只保留不超過 3 個精要目標，其餘明確降級或拒絕。
2. **公開 intake 規則，專案啟動先簽"社會契約"**：把"說不"寫成團隊預設流程，減少每次拒絕的情緒成本。
3. **每個任務先寫"完成長什麼樣"**：可觀察的驗收標準，寫進工單。
4. **區分兩個"簡化"**：先刪專案（精要主義的「簡化」），再刪步驟（輕鬆主義的「簡化」）。
5. **寫下第一個顯而易見的動作**：小到 5 分鐘內能開始，比如建分支、寫失敗的測試、開 Draft PR。
6. **允許零稿**：設計和程式碼先發草稿，早求反饋，靠迭代達到品質。
7. **設節奏上下限**：WIP 上限、每天的最小進展和最大投入、固定的收工時間。
8. **守住恢復線**：不在一天裡做超過第二天早上能恢復的量；上午留出深度工作塊，每塊不超過 90 分鐘。
9. **每月消滅一件 toil**：用"最煩人、最省時"的標準挑一項，做成指令碼、checklist 或 Runbook。
10. **復盤時追問"預防"**：每次事故至少產出一項讓同類問題不再發生的改動。
11. **搭建高信任結構**：明確 owner、契約、SLO 和自主決策邊界；不替別人扛下本該由他們解決的問題。
12. **定期問一句**：我是不是把事情弄得比必要的更難了？（"how am I making things harder than they need to be?"；臺版：「會不會這其實可以很簡單？」）
