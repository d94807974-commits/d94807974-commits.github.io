几个值得注意的细节：

- **繁体版比简体版来得早。** 《少，但是更好》比简体版早了一年半；《努力，但不費力》与 Effortless 英文版只隔八个月，比简体版也早了两三个月。
- **台版两本书同日出新版。** 天下文化在 2021-12-29 同时推出了《少，但是更好（新編增訂版）》和《努力，但不費力》，显然是当作一套书来经营的。2025 年，天下文化又把《少，但是更好》和一本《90天生活實踐》（周羣英 译）合成两册套书。
- **作者译名不同。** 台版作者名译作「葛瑞格．麥基昂」，简体版译作"格雷戈·麦吉沃恩"。

天下文化的作者简介写道：作者在史丹佛大学与人合开「設計精簡生活」（Designing Life, Essentially）课程，曾获世界经济论坛任命为「青年全球領袖」，并主持 Podcast《What's Essential》。

## 二、两岸译本对照：同一套框架，两种中文

把三个版本的目录放在一起读，最大的收获不是信息量，而是**译名本身就是一种解读**。

### 1. 书名：一个强调"主义"，一个强调"取舍"与"努力"

简体版把两本书译成"××主义"，读者一眼就知道它们是一个系列。台版的书名走了另一条路：

- 《少，但是更好》直译作者的口号 *Weniger aber besser*。
- 《努力，但不費力》把一对看似矛盾的词放在一起。

我认为后者翻得更准。"轻松主义"四个字很容易被读成"偷懒有理"，而「努力，但不費力」先承认了努力，再讨论怎样不白费力气。这正是作者在访谈里反复澄清的那条线（见第四节）。

### 2. 《精要主义》的三步：精挑、简化、准确执行

台版把 Essentialism 译作「專準主義」，并把三个部分压缩成一个口诀：「精．簡．準」。时任台大管理学院院长的郭瑞祥在推荐语里写道，这本书在教人成为「精．簡．準」（精挑、簡化、準確執行）的專業工作者」。

| 英文 | 简体中文版 | 繁体中文版（台湾） |
|---|---|---|
| Essence（核心思维） | 核心思维模式：选择 / 甄别 / 取舍 | 追求本質：懂得選擇 / 懂得辨別 / 懂得取捨 |
| Explore | 探索：抽离 / 审视 / 游戏 / 睡眠 / 精选 | 精挑：逃離 / 留意 / 玩樂 / 睡眠 / 嚴選 |
| Eliminate | 排除：澄清 / 勇气 / 放弃 / 编辑 / 边界 | 簡化：釐清 / 膽量 / 取消承諾 / 剪輯 / 界線 |
| Execute | 执行：缓冲 / 扫除 / 进步 / 心流 / 专注 | 準確執行：緩衝 / 減法 / 進展 / 心流 / 專注 |

几处差异值得注意：

- **Eliminate**：简体版译作"排除"，台版目录的部名却叫「簡化」，副标题是「如何排除瑣碎的多數？」。天下文化刊出的前言书摘里，同一步又写作「簡化、排除」。创业媒体 Innopreneur 的繁体文章则用「消除」。这样一来，*Effortless* 第八章 Simplify 在简体和繁体里都叫"简化"，但在台版《少，但是更好》里，「簡化」指的是删项目。两本书合读时，一定要分清两个"简化"：前者删的是要不要做的事，后者删的是怎么做里的步骤。
- **Unschedule / Subtract**：简体版的"放弃"、"扫除"，台版分别作「取消承諾：停損贏更大」和「減法：移除障礙，事半功倍」。「減法」两个字比"扫除"更贴近原意：不是加把劲，而是拿掉阻碍。
- **新编增订版的改动**：台版新编增订版把二十章加附录改排成〈二十一天專準主義挑戰〉的第一天到第二十一天，比如「剪輯：隱形的藝術」「界限：有界限，才有自由」。初版目录里的「界線」也改成了「界限」。

### 3. 《轻松主义》：台版译名更"动作化"

| 英文 | 简体中文版 | 繁体中文版（台湾） |
|---|---|---|
| Effortless State | 轻松状态：倒置 / 享受 / 释怀 / 休息 / 觉察 | 不費力的狀態：翻轉 / 享受 / 釋放 / 休息 / 察覺 |
| Effortless Action | 轻松行动：定义 / 开始 / 简化 / 过程 / 节奏 | 不費力的行動：界定 / 起跑 / 簡化 / 推進 / 步調 |
| Effortless Results | 轻松成果：学习 / 提升 / 自动 / 信任 / 预防 | 不費力的成果：學習 / 提升 / 自動化 / 信任 / 預防 |

台版的章名副标题也很好用，几乎可以直接当成工程团队的口号：

- 「界定：『完成』是什麼樣子」
- 「起跑：顯而易見的第一步」
- 「推進：產出垃圾的勇氣」
- 「步調：慢即穩，穩即快」
- 「自動化：做一次就好」
- 「信任：發動高績效團隊的引擎」

## 三、两本书各自讲了什么

### 《精要主义》：做"对的事"

出版社的定位一句话说清了这本书："Essentialism isn't about getting more done in less time. It's about getting only the right things done."（精要主义不是在更少的时间里做更多事，而是只做对的事。）

天下文化刊出的前言书摘里，作者讲了一段亲身经历：女儿刚出生几个小时，同事写信说那天下午的客户会需要他出席，他去了。事后他承认那场会「毫無成果可言」，自己「在想讓每個人都開心的情況下，我犧牲了最要緊的事」。他从中得到的教训是：

> 「如果你不替自己的生活排定優先次序，別人就會代勞。」（《少，但是更好》前言书摘，天下文化 Bookzone）

作者用"整理衣柜"来比喻全书的三步：

1. 不问「我以後還有沒有機會穿這件衣服？」，而问「我喜歡這件衣服嗎？」；
2. 把不要的真正装袋送走；
3. 建立一套定期清理的例行流程。

### 《轻松主义》：把对的事"做轻松"

官网和出版社的简介点出了它要反驳的信念："That if we want to overachieve, we have to overexert, overthink, and overdo."（想要超常成就，就必须用力过猛、想得过多、做得过头。）它的立场是："The effortless way isn't the lazy way. It's the smart way."（轻松之道不是偷懒之道，而是聪明之道。）

台版的文案换了个说法讲这件事：我们习惯把事情分成「困難而重要」和「簡單而瑣碎」两类，「其實我們還有第三種選擇：把重要但困難的工作變得簡單。」（天下文化《努力，但不費力》书籍页）

## 四、整合：一个讲"做什么"，一个讲"怎么做"

### 1. 证据：第一本书就预告了第二本

把两本书看成"上下集"，并不只是我的读法。天下文化刊出的《少，但是更好》前言书摘里，作者在讲第三步时写道：

> 「一旦你釐清要保留的是哪些活動和努力⸺⸺使你能做出最高程度貢獻的那些⸺⸺你就需要一套能讓你盡可能輕鬆執行意圖的系統。在本書中，你將學習創造出一個使必要的事情盡可能輕鬆完成的過程。」

Innopreneur 的文章引用了原书中的英文："While Nonessentialists tend to force execution, Essentialists invest the time they have saved by eliminating the nonessentials into designing a system to make execution almost effortless."（非精要主义者倾向于硬推执行；精要主义者则把排除杂事省下的时间，投入到设计一套让执行几乎不费力的系统上。）这里已经出现了 effortless 这个词。

作者在 Jordan Harbinger 的访谈里，也把《精要主义》的落点概括为"how to build systems to make execution of what is essential, as easy as possible"（建立系统，让精要之事执行起来尽可能容易）。

《努力，但不費力》的台版书摘则把接力棒说得更直接：

> 「當手上重要的事已經超出你所能負荷，你可以選擇割捨，或是找輕鬆的方法來做。《努力，但不費力》要談的則是，用對的方法來做對的事。」（〈別把「過勞倦怠」當成榮譽勳章！〉，天下文化 Bookzone，2021-12-22）

台湾读书博客「超閱者」的一句话概括，正好是本文的标题：「如果說《少，但是更好》是教你如何做對的事情；這本書則是教你如何用對的方法來做對的事。」

### 2. 精要主义的陷阱：减法做完了，剩下的仍然在硬扛

精要主义最常见的失败方式，并不是没做减法，而是做完减法后，用加倍的意志力去对付剩下的每一件事。"既然这件事最重要，就该拼尽全力。"结果是：重要的事少了，人却更累了。

台版书摘开篇讲了 Patrick McGinnis 的故事。他在 AIG 每周工作 80 小时，2008 年公司崩盘，他手上的股票跌了 97%。他事后的结论被译成：

> 「我解決所有問題的方式，就是花更多時間、再努力一點。」但突然之間，他發現，「再努力一點的邊際報酬竟然是負的。」

作者由此得出的教训是：「當你已經沒辦法再多努力一點，就是時候另覓出路了。」作者和天下文化编辑张彤华的导读都借用了《动物农庄》里的马「拳擊手」：牠面对每一次挫折和每一个难题，回答总是「我會更努力的。」，最后积劳成疾，被送进老弱家畜屠宰场。

作者在 Next Big Idea Club 的长文里，讲的是女儿 Eve 重病的经历。这件事绝对属于精要，但这场仗要打多久没人知道："If your job is to keep the fires burning for an indefinite period, you can't throw all the fuel on the flames at the beginning."（如果你的任务是让火无限期地燃烧，就不能一开始把所有燃料都扔进去。）

所以两本书合起来，构成一个完整的闭环：

```
          《精要主义》：做什么                    《轻松主义》：怎么做
  ┌──────────────────────────────┐    ┌──────────────────────────────────┐

  │ 探索（精挑）：抽离 审视 游戏 睡眠 精选│ │  （先把"人"调到能清醒选择的状态）       │
```

### 3. 一个关键区分：轻松不等于偷懒

作者在访谈里专门划了这条线："Lazy is an unwillingness to work. Easy is just something doesn't require a lot of effort to get it done."（懒是不愿工作；容易只是指一件事不需要大量努力就能完成。）他还说："Effort is a finite resource."（努力是有限的资源。）

台版文案的说法几乎一致：「問題在於動力和努力都是有限的資源，我們愈是消耗，就愈容易過勞」。这句话把两本书统一成一个经济学问题：精要主义管"把有限的努力投向哪里"，轻松主义管"每单位努力能换来多少产出"。

### 4. 技术负责人身上的典型陷阱

我见过不少技术负责人，精要主义做得很好：季度目标只留三个，杂事推得干干净净。可那三件事，每一件都靠自己通宵顶上去：核心模块自己写，关键评审自己看，线上事故自己冲在第一线。

短期看，这是"聚焦"；长期看，这就是拳擊手式的「我會更努力」。团队的能力没有长起来，负责人自己成了系统里唯一的瓶颈，也就是《精要主义》里的"最慢行进者"。

轻松主义给的出路不是"再砍一件"，而是换一个问题：怎样让这件事不依赖我的透支也能完成？答案往往落在三个地方：

- 把知识写下来，让别人能接手（学习、提升）；
- 把重复劳动交给脚本（自动）；
- 把决策权交给可信的人（信任）。

## 五、放到工程师与技术负责人的日常

### Backlog 排序：先用精要主义砍，再用轻松主义拆

- **砍**：给每个需求问一句，它能不能进前 10%？豆瓣读者摘录的简体中译本里有一句判断规则："如果答案不是一个确定的yes，那么就应该是一个肯定的no"。真实的 backlog 很难做到这么绝对，但可以把"不确定"的需求统一放进"下季度再评估"，不让它占用本迭代的容量。
- **拆**：对留下的需求，依次问轻松主义的几个问题：完成长什么样？哪些步骤可以删掉？第一个显而易见的动作是什么？

### 说"不"：把拒绝做成机制，而不是每次靠勇气

天下文化刊出的「界限」一章书摘，开头引了 Anne Lamott 的一句话：「不，就是完整的句子。」这一章里有两个对工程团队特别有用的做法。

**一是「社會契約」。** 作者和一位作风相反的同事搭档，第一次开会就先讲清各自的优先事项，以及自己愿意或不愿意承担的额外工作。

**二是「別搶他人的問題」。** 原文是：「一旦我們替他們扛下問題，我們所做的一切不過是在奪走他們解決問題的能力而已。」

这两点可以沉淀成轻松主义式的"一次性决定"。出版社简介的说法是"Make one-time choices that eliminate many future decisions"。落到团队里：

- 公开 intake 规则和本季度目标，不在目标里的需求，默认进入排队；
- 设立值班"接口人"，其余人默认不接插单；
- 项目启动会先写一份"社会契约"：本期目标、各自不接的事、升级路径。

作者在同一章里提醒：「如果你不設定界限，就不會有任何界限。」《远见》杂志 2014 年的报道引了另一句：「只要你無法對不必要的事情說不，就等於在消極被動情況下說好。」

### 定义"做完"：避免瓦萨号式的范围蔓延

在访谈里，作者和主持人谈到了那艘瑞典战舰（瓦萨号）。作者说它"not fit for purpose"（不适合它原本的用途），因为造船的人从来没有定义清楚"完成"长什么样。主持人当场就把它类比成软件项目里的 feature creep（功能蔓延）。

工程上的对应物就是 Definition of Done：验收标准、性能指标、回滚方案、文档，在开工前写下来。作者给自己的书定过一个"完成"的样子："I've given this to my editor and she has looked through all of the chapters and said, 'Every one of them is solid and great.'"（我交给编辑，她看完所有章节后说：每一章都扎实而出色。）这个标准是可观察的，不是"我觉得写好了"。

### 第一个显而易见的动作 + 零稿

作者在访谈里说，完美主义让人迟迟不开始；他的办法是写一份"零稿"："You don't publish rubbish, but you got to be willing to stare at rubbish."（你不会发布垃圾，但必须愿意直视垃圾。）台版第九章的章名把这个意思译得很传神：「推進：產出垃圾的勇氣」。

落到工程上就是：

- 先开一个 Draft PR；
- 先写一个能跑通主路径的 spike；
- 设计文档先写成提纲，第一天就请同事看。

第一个动作应该简单到不需要任何心理建设，比如"新建分支，写一个失败的测试"。

### 节奏：给工作量设上下限，也给恢复留出时间

作者用阿蒙森与斯科特的南极竞赛说明节奏的价值：阿蒙森坚持每天前进约 15 英里，"no more and no less"（不多也不少）。作者建议给工作量同时设下限和上限，例如写书"never write less than 500 words a day, but never more than a thousand"（每天不少于 500 字，也不多于 1000 字）。

台版「休息」一章的书摘给了一条更严格的规则：

> 「切勿在一天之內做超過隔天一早可以完全恢復的事情，切勿在一週之內做超過隔週一開始可以徹底恢復的事情。」

书摘还给了一个具体排法：「利用早上處理重要工作」，「分三個時段工作，每個時段不超過90分鐘」，中间休息 10 到 15 分钟。

工程团队的对应做法是：

- 设 WIP（在制品）上限；
- 每天至少合并一个小 PR，但不在一天里堆十个；
- 上午留出两到三个不开会的深度工作块；
- 值班或救火之后，第二天主动降负荷。

《远见》的报道还提到，LinkedIn 执行长 Jeff Weiner 每天会在行事历里预留两个小时空档。

### 自动化与预防：时间管理的"长尾"

作者举过一个例子：有人被一只卡住的抽屉烦了两年，修好它只用了两分钟。他的总结是："it usually takes less time to manage a problem than to solve it."（应付一个问题，通常比解决它花的时间少。）这正是 SRE 说的 toil（重复性杂务）。目标是"find the most annoying thing that can be solved in the least amount of time"（找到最烦人、又能用最少时间解决的那件事）。

台湾「閱讀前哨站」的书评补了一个有意思的视角。作者把"检查清单"放进「自動化」一章，书评把它概括为「大腦決策的自動化」。书评里还举了一个例子：有人原本每到交周报那天都要忙到很晚，后来改成每天下班前用一到两行话记下进度，到交周报时只要整理一下就行。

对工程团队来说，可以这样落地：

- 用脚本替换手工发布、手工对账；
- 把发布、回滚、事故处置写成 checklist 和 Runbook，相当于"决策的自动化"；
- 每天在工单里留一行进展，周报自动汇总；
- 在复盘里追问"怎样让这类问题根本不会发生"，对应「預防：預見問題，防患未然」一章。

### 信任：低信任结构是自动出现的

豆瓣读者摘录的第 14 章简体中译本里写道：在低度信任结构中，"规则模棱两可，没人知道成功的标准是什么"；而"低度信任结构通常是自动出现的，而不是有意为之"。

技术负责人要刻意搭建高信任结构：

- 写清楚每个模块的 owner；
- 写清楚接口契约和 SLO；
- 写清楚什么情况下可以自行决定。

信任一旦建立，Review 和审批就可以变轻。台版把这一章叫做「信任：發動高績效團隊的引擎」。

## 六、我的思考：两本书的不足

**第一，过度假设个人拥有选择权。** 两本书的读者画像，是能够自主安排时间的知识工作者。一线工程师的 backlog 往往由产品、老板和合规要求共同决定，"确定的 yes 或肯定的 no"在组织里很难由个人说了算。

有意思的是，「界限」一章的书摘里，作者自己也承认：「界限確實可能付出昂貴的代價。」我认为更现实的做法是把精要主义上移到团队层面：由技术负责人和产品负责人一起做取舍，再由个人去执行轻松主义。

**第二，故事多、证据少，第二本更浅。** 两本书都大量依靠故事：南极竞赛、瓦萨号、抽屉、女儿的病、McGinnis 的 AIG 往事。故事好记，但因果关系往往被简化了。以斯科特的失败为例，常见的解释远不止"节奏"一项，还包括运输方式和补给安排。

「閱讀前哨站」的评价很中肯：他对《少，但是更好》评价不错，但《努力，但不費力》让他觉得有点「搔不到癢處」，每个小节篇幅太短，读起来「淺嚐即止」。如果你想「學習實踐步驟」，这本书「比較像是給予一些原則和基本指引」。这和豆瓣短评里"主旨很好……但是内容稍显啰嗦"的感受，算是两岸读者的共识。

**第三，"轻松"容易被滥用。** 作者再三强调"easy does not equal lazy"，但在团队里，"找更轻松的路"也可能被用来跳过测试、省略评审。台版书名「努力，但不費力」在这点上是一个很好的提醒：努力本身没有被取消。我的补丁是：可以简化步骤，不能降低"完成"的标准。先定义完成，再谈轻松。

**第四，重复和"鸡汤感"。** 两本书有大量重叠，比如休息与睡眠、边界与节奏、小胜。如果只读一本，我建议读《精要主义》的框架，再把《轻松主义》当作"执行"部分的工具书来查。

**第五，宗教与个人信仰色彩。** 天下文化刊出的《少，但是更好》书摘（从内容看出自最后一章「存在」）从甘地写到释迦牟尼、摩西、穆罕默德和耶稣，称「專準主義在許多靈性和宗教傳統中具有深厚的根基」。《努力，但不費力》的「釋放」一章则大量讨论感恩。这些内容对部分读者有帮助，但不是方法的必要组成部分，阅读时可以剥离开。

## 七、可执行清单

1. **每季度做一次"前10%"筛选**：列出所有项目，只保留不超过 3 个精要目标，其余明确降级或拒绝。
2. **公开 intake 规则，项目启动先签"社会契约"**：把"说不"写成团队默认流程，减少每次拒绝的情绪成本。
3. **每个任务先写"完成长什么样"**：可观察的验收标准，写进工单。
4. **区分两个"简化"**：先删项目（精要主义的「簡化」），再删步骤（轻松主义的「簡化」）。
5. **写下第一个显而易见的动作**：小到 5 分钟内能开始，比如建分支、写失败的测试、开 Draft PR。
6. **允许零稿**：设计和代码先发草稿，早求反馈，靠迭代达到质量。
7. **设节奏上下限**：WIP 上限、每天的最小进展和最大投入、固定的收工时间。
8. **守住恢复线**：不在一天里做超过第二天早上能恢复的量；上午留出深度工作块，每块不超过 90 分钟。
9. **每月消灭一件 toil**：用"最烦人、最省时"的标准挑一项，做成脚本、checklist 或 Runbook。
10. **复盘时追问"预防"**：每次事故至少产出一项让同类问题不再发生的改动。
11. **搭建高信任结构**：明确 owner、契约、SLO 和自主决策边界；不替别人扛下本该由他们解决的问题。
12. **定期问一句**：我是不是把事情弄得比必要的更难了？（"how am I making things harder than they need to be?"；台版：「會不會這其實可以很簡單？」）
